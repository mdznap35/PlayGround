# خارطة الطريق الكبرى — CineForge Studio

**الإصدار:** 2.0  
**آخر تحديث:** 2026-11-03  
**فرع التنفيذ الحي:** `feat/cineforge-cinematic-media-v2`  
**رابط الاستوديو:** https://cineforge-studio-b92r.onrender.com/  
**مبدأ المنتج:** أقوى نظام عملي ممكن ضمن حدود مجانية حقيقية، يعمل من الهاتف، ويقول بوضوح كيف صُنعت كل لقطة.

> هذه وثيقة تنفيذ واختبار، وليست وعداً بأن جميع المراحل منجزة. كل مرحلة لا تُعتبر مكتملة حتى تنجح معايير قبولها ويُحفظ دليلها في GitHub.

## 1. الرؤية النهائية

بناء استوديو عربي متكامل لإنتاج الفيديوهات القصيرة والطويلة والسينمائية، يبدأ من الفكرة وينتهي بملف قابل للنشر، عبر خط إنتاج واضح:

**فكرة وموجز → قصة وسيناريو → لوحة لقطات → أصول مرئية وصوتية → مونتاج وتركيب → ترجمة وتوقيت → فحص جودة → حزم تصدير.**

المنتج النهائي يجب أن يتيح للمستخدم:
- إنشاء فيديو وثائقي أو تعليمي أو قصصي أو إعلاني أو سينمائي.
- العمل على أفقي 16:9 وعمودي 9:16 ومربع 1:1، ثم إضافة ملفات تسليم مخصصة للمنصات.
- تخطيط القصة واللقطات، وتحديد الهدف السردي لكل مشهد.
- إضافة الصور واللقطات المرخصة والمواد الخاصة بالمستخدم، مع معرفة مصدر كل أصل وحقوق استخدامه.
- ضبط التعليق الصوتي والموسيقى والمؤثرات والترجمة العربية.
- تركيب المشاهد والحركة والانتقالات والنصوص، ثم إنتاج MP4 قابل للفحص.
- استعادة المشروع وتصديره من الهاتف دون الحاجة إلى حاسوب.
- معرفة ما إذا كانت اللقطة مولّدة بالذكاء الاصطناعي أو صورة ثابتة متحركة أو فيديو مرفوعاً أو رسماً حركياً تقليدياً.

## 2. قواعد لا يجوز تجاوزها

1. **مجاني أولاً:** لا اشتراك مدفوع، ولا API مدفوع، ولا رصيد تجريبي يُقدَّم على أنه مجاني دائم، ولا خدمة مدفوعة تُفعَّل تلقائياً.
2. **لا تنزيلات مفاجئة:** قبل تنزيل نموذج أو مكتبة كبيرة أو مجموعة أصول، يُذكر الحجم المتوقع وحجم النقل والغرض، ويُطلب الإذن.
3. **لا ادعاء مضلل:** محرك FFmpeg الحالي يركّب صوراً وصوتاً ورسومات متحركة؛ لا يجوز تسميته مولّداً واقعياً للفيديو.
4. **خصوصية الملفات:** المستودع عام. لا تُرفع إليه تسجيلات صوت شخصية أو صور خاصة أو مواد غير مرخصة أو أسرار. نستخدم عينات اصطناعية في CI.
5. **مصدر الحقوق:** كل صورة أو مقطع أو موسيقى مستخدمة فعلياً لها مصدر وحالة ترخيص/إذن. لا يكفي أن تكون متاحة للتنزيل.
6. **الاستفادة من المفتوح المصدر:** ندرس المشاريع المفتوحة ونستفيد من الأفكار والواجهات والبنية والمكتبات المناسبة، لكن لا ننسخ كوداً أو أصولاً قبل مراجعة الترخيص والإشعارات والاعتماديات.
7. **حدود الاستضافة:** Render يستضيف واجهة الويب الثابتة. GitHub Actions ينفذ اختبارات ورندرة CPU محدودة؛ لا يُعامل كخادم GPU دائم أو تخزين دائم.
8. **لا دمج دون مراجعة:** تبقى الفروع وطلبات الدمج منفصلة حتى اكتمال اختبارات المرحلة ومراجعة التغييرات. لا دمج آلي إلى `main`.

## 3. البنية المجانية المعتمدة

| الجزء | الاستخدام |
|---|---|
| GitHub | الكود، التوثيق، التغييرات المراجعة، اختبارات CI، وملفات مشروع صغيرة غير خاصة |
| Render Static Site | واجهة CineForge المنشورة؛ لا رندرة فيديو داخل خادم الويب |
| GitHub Actions CPU | فحوصات المشروع، FFmpeg، إنتاج MP4، وتقارير الجودة ضمن الحصص المتاحة |
| المتصفح | تحرير فوري وحفظ مسودة محلية، ثم تصدير JSON |
| Canva | تسليم اختياري لتصميم الهوية والصور المصغّرة والقوالب، دون جعله اعتماداً إلزامياً |
| موصلات الذكاء الاصطناعي | اختيارية ومعزولة؛ لا تفعّل إلا بعد التحقق من الحصة المجانية والترخيص والخصوصية والأهلية |

الحصص المجانية لها حدود واحتفاظ مؤقت. لذلك يجب تنزيل ملفات MP4 المهمة إلى جهاز المستخدم وعدم الاعتماد على بقاء Artifacts إلى الأبد.

## 4. مراحل التنفيذ ومعايير القبول

### المرحلة 0 — الأساس والاستوديو الأولي <small>منجزة ومثبتة سابقاً</small>

**الموجود:** واجهة عربية متجاوبة، محرر مشاهد، مخطط JSON، معاينة تصميمية، حفظ محلي، ورندرة MP4 بواسطة Pillow وFFmpeg.

**معيار القبول:** ملف قديم صالح يبقى قابلاً للتحقق والرندرة، وتبقى العربية مقروءة، وتُفحص أبعاد الفيديو ومعدل الإطارات والترميز.

### المرحلة 1 — محرك الوسائط السينمائي <small>منجزة على PR مسودة</small>

**الموجود:** صورة لكل مشهد، سبع حركات كاميرا، تعليق صوتي وموسيقى بمستويين منفصلين، التحقق من مسارات الوسائط، وفحص FFprobe.

**اختبارات القبول المسجلة:** 19 اختبار Python على تنفيذ المرحلة؛ اختبار تكاملي يصنع صورة وصوتاً اصطناعيين ثم يفحص H.264 و1920×1080 و24fps وAAC. لا يحتوي المستودع على وسائط المستخدم الخاصة.

### المرحلة 2 — من مخطط القصة إلى مشاهد قابلة للرندرة <small>التنفيذ الجاري</small>

**الهدف:** ألا تكون خطة القصة صفحة منفصلة فقط؛ يجب أن تنتقل إلى محرر المشاهد دون إعادة كتابة يدوية.

**التنفيذ:**
- استيراد ملف `cineforge.story-plan` الإصدار 2 من صفحة مخطط القصة.
- فحص البنية وعدد المراحل والحقول النصية قبل قبول الملف.
- توزيع مدة الفيديو حسب وزن المراحل، مع احترام 3–90 ثانية لكل مشهد وحد إجمالي 15 دقيقة لمحرك الرندر الحالي. ولأن صفحة المخطط تبدأ بسبع مراحل، فإن التحويل المباشر لمشهد واحد لكل مرحلة يصل حالياً إلى 10.5 دقائق كحد أقصى؛ يمكن إضافة لقطات أخرى من لوحة المشاهد، ويُخطط لاحقاً لتقسيم المرحلة الواحدة إلى عدة لقطات تلقائياً.
- تحويل عنوان المرحلة ومحتواها ووصفها البصري إلى مشهد قابل للتحرير.
- الاحتفاظ بنسخة منظمة من الجمهور والهدف والشخصيات والمواقع والعناصر والمصادر كبيانات تخطيطية في ملف المهمة.
- الحفظ المحلي والاستعادة بعد إعادة فتح الصفحة.
- رفض ملف غير معروف أو مدة لا يمكن توزيعها برسالة واضحة، دون فقدان المسودة الحالية.

**معايير القبول:**
- استيراد خطة عربية من صفحة مخطط القصة إلى لوحة المشاهد.
- مجموع مدد المشاهد يساوي مدة الخطة تماماً.
- لا يتجاوز أي مشهد 90 ثانية ولا يتجاوز المشروع 900 ثانية.
- تبقى بيانات الاستمرارية والمصادر موجودة في JSON المصدر.
- لا تتغير صيغة الرندر القديمة `schema_version: 1`.
- اختبارات Node تغطي الملف الصحيح، الملف المشوّه، التوزيع، الحدود، وحفظ البيانات الوصفية.

### المرحلة 3 — مكتبة الأصول وسجل المصدر والحقوق

**الهدف:** كل لقطة لها أصل معروف، ولا تضيع الملفات بين المشاهد.

**المهام:**
1. بناء Media Bin يعرض الصور والمقاطع والصوتيات مع الاسم والنوع والحجم والأبعاد والمدة.
2. إضافة أصل من الهاتف عبر منتقي الملفات، مع معاينة محلية دون رفع تلقائي إلى خادم.
3. توليد بصمة SHA-256 عبر Web Crypto لكل ملف، وتخزين مرجع الأصل ضمن المشروع.
4. سجل حقوق لكل أصل: المالك/المصدر، رابط المصدر، نوع الترخيص أو الإذن، القيود، وتاريخ التحقق.
5. تمييز الحالات: موثق، يحتاج تحققاً، مسموح للاستخدام الشخصي فقط، أو ممنوع/غير معروف.
6. ربط الأصل بمشهد واحد أو عدة مشاهد مع إمكانية استبداله دون تغيير بقية المشروع.
7. فحص الأبعاد والتناسب والامتداد والحجم، وإظهار الأصول المفقودة قبل الرندر.
8. إنشاء تقرير يبيّن اللقطات التي لا تملك أصلاً أو حالة حقوق واضحة.

**الاستفادة المفتوحة:** تقييم أدوات إدارة الأصول المفتوحة ومكتبات قراءة الميتاداتا، مع الاعتماد على معايير مفتوحة. تُراجع تراخيص أي مكتبة قبل إضافتها، ولا نضيف اعتماداً ضخماً لو أمكن تنفيذ الوظيفة بأداة متصفح صغيرة.

**معايير القبول:** يستطيع المستخدم معرفة مصدر وحقوق كل أصل مستخدم؛ لا يصدّر المشروع النهائي بصمت إذا كان أصل مطلوب مفقوداً؛ واستبدال أصل لا يعدّل أصول المشاهد الأخرى.

### المرحلة 4 — التعليق الصوتي والترجمة العربية

**الهدف:** صوت وترجمة متزامنان مع القصة، لا مجرد ملفات صوت مرفقة.

**المهام:**
1. مسارات مستقلة للتعليق والموسيقى والأجواء والمؤثرات، مع كسب صوتي وتلاشي دخول/خروج.
2. ملاحظات نطق عربية، وتطبيع اختياري للنص قبل تحويله إلى صوت.
3. محرر ترجمة لكل مقطع مع وقت بداية ونهاية، ويدعم RTL والتشكيل والأرقام.
4. استيراد وتصدير SRT وWebVTT مع فحص ترتيب الطوابع الزمنية وعدم تداخلها.
5. مناطق آمنة للنص في 16:9 و9:16 و1:1.
6. فحص الترجمة: طول السطر، سرعة القراءة، كثافة الكلمات، ومدة العرض.
7. تحليل مدة التعليق مقارنة بمدة المشهد، مع تحذير من الكلام السريع أو الفراغ غير المقصود. (تم تنفيذ تقدير أولي لكل مشهد؛ يلزم لاحقاً ربطه بتوقيت صوت فعلي وقياس الصمت والذروة.)
8. فحص الصوت: وجود المسار، الذروة، القصّ، الصمت الطويل، ومدى مطابقته للمدة.

**معايير القبول:** ملف SRT/VTT صالح، نص عربي سليم الاتجاه، التوقيت ضمن مدة الفيديو، تقرير واضح للصوت، ولا تُنشأ أصوات مستنسخة أو تُستخدم هوية صوت شخص دون إذن.

### المرحلة 5 — المونتاج والتركيب السينمائي

**الهدف:** نقل النظام من ترتيب بطاقات إلى خط زمني مرئي متعدد الطبقات.

**المهام:**
1. Timeline بمسارات للصورة/الفيديو، العناوين، الترجمة، التعليق، الموسيقى والمؤثرات.
2. قصّ بداية ونهاية اللقطة، وإعادة ترتيب المقاطع، وتقسيم اللقطة، وضبط السرعة ضمن ما يدعمه المحرك.
3. انتقالات أساسية قابلة للقياس: Cut وFade وDissolve، ثم Match Cut عند توفر اختبار بصري مناسب.
4. طبقات عنوان وLower Third وبطاقات أرقام ورسوم معلوماتية.
5. قوالب ألوان وخطوط وتكوين متسقة مع دليل الهوية.
6. مكتبة حركات كاميرا ومخططات جاهزة، قابلة للتعديل لكل مشهد.
7. مزج صوتي مع خفض تلقائي اختياري للموسيقى أثناء الكلام (Ducking).
8. حفظ إعدادات كل لقطة وإعادة إنتاجها من manifest واضح.

**الاستفادة المفتوحة:** دراسة معماريات Shotcut وKdenlive وOlive وFFmpeg وغيرها كمرجع لتقسيم الخط الزمني والمسارات، لا نسخ شيفراتها دون مراجعة الترخيص. تُستخدم FFmpeg كطبقة التركيب الأساسية، مع إبقاء واجهة الهاتف خفيفة.

**معايير القبول:** ترتيب اللقطات والمدد يطابق Timeline؛ انتقالات قابلة للاختبار؛ وتبقى ملفات المشاريع السابقة صالحة.

### المرحلة 6 — الجودة والتصدير الاحترافي

**الهدف:** لا يقال إن الفيديو جاهز لمجرد أن أمر FFmpeg انتهى.

**المهام:**
1. ملف QA موحد يتضمن الترميز والأبعاد والإطارات والمدة والحجم ومعدل البت ومسارات الصوت.
2. فحص وجود الإطارات السوداء أو الثابتة المفرطة أو الصمت غير المتوقع عند الإمكان.
3. مقارنة مدة الناتج مع Timeline، والتحقق من آخر إطار وآخر صوت.
4. اختبارات توافق للمقاسات الأفقية والعمودية والمربعة.
5. صورة مصغرة ولقطة افتتاحية وبيانات تسليم خاصة بكل منصة.
6. إصدارات Render مرقمة مع بصمة SHA-256 للملف النهائي وإعدادات الإنتاج.
7. حالات مهمة واضحة: Draft، Validated، Queued، Rendering، QA Failed، Ready، Downloaded.
8. إعادة تشغيل المهام الفاشلة دون تكرار تنزيل الأصول أو تنفيذ مؤثرات غير لازمة.
9. صفحة تقرير أخطاء قابلة للقراءة من الهاتف.

**معايير القبول:** لا تتحول المهمة إلى Ready إلا بعد نجاح فحوصاتها الإلزامية؛ ويتضمن كل ملف نهائي تقريراً تقنياً وبيانات إعادة الإنتاج.

### المرحلة 7 — موصلات التوليد بالذكاء الاصطناعي، اختيارياً

**الهدف:** إضافة لقطات مولّدة حقيقية عندما توجد سعة مجانية مثبتة، دون ربط المنتج بمزود واحد.

**المهام:**
1. عقد Provider Adapter موحد يصف المهام والقيود والحالات والحصة والترخيص والتكلفة.
2. فصل الإرسال والاستعلام والتنزيل والإلغاء وإعادة المحاولة عن الواجهة.
3. مفتاح idempotency لمنع إرسال نفس الطلب مرتين عند إعادة المحاولة.
4. فحص نوع الملف وحجمه ومصدر التنزيل قبل قبول الناتج.
5. تسجيل المزود والنموذج والإصدار والإعدادات والبصمة والرخصة لكل لقطة.
6. اختبار قصير بمواد غير خاصة فقط، بعد التحقق من أهلية الحساب والمنطقة والحصة.
7. إيقاف تلقائي واضح عند نفاد الحصة أو عدم توفر الخدمة، والعودة إلى مسار الصور والحركة العادي.

**شرط المجانية:** لا يُسمى الموصل مجانياً إلا إذا أثبتت الوثائق الرسمية وجود حصة متجددة للطرفية المحددة، بلا خطة مدفوعة إلزامية، وبلا مفاجآت فواتير. الأرصدة التجريبية والصفحات العامة المشتركة ليست ضماناً للإنتاج. لا تُنزّل أوزان نماذج أو ملفات ضخمة قبل تقدير الحجم والحصول على إذن.

**معايير القبول:** مقطع واحد حقيقي يمر من الطلب إلى التنزيل والتدقيق، مع توثيق الحصة والترخيص والزمن والقيود؛ وإلا يبقى الموصل غير مفعّل ولا يؤثر على بقية الاستوديو.

### المرحلة 8 — تشغيل الهاتف والإطلاق

**المهام:**
1. اختبار تدفق العمل كاملاً على شاشة هاتف صغيرة ومتصفح Android.
2. التأكد من أن منتقي الملفات والتنزيل وفتح JSON ورفع الأصول واضحة.
3. توفير نسخة احتياطية للمشروع وملف manifest مع استعادة مجرّبة.
4. إظهار تحذير واضح بأن Local Storage مسودة محلية لا نسخة احتياطية.
5. تقليل حجم JavaScript وعدم تحميل مكتبات أو خطوط غير لازمة.
6. اختبار قارئ الشاشة ولوحة المفاتيح والتباين وحجم أهداف اللمس.
7. نشر واجهة ثابتة على Render، بينما تبقى عمليات الفيديو في Actions أو موصل موثوق.
8. دليل استخدام عربي قصير يبدأ من مشروع جديد وينتهي بتنزيل MP4.
9. مراجعة خصوصية المستودع العام قبل أي إطلاق؛ لا تُضمّن بيانات أو ملفات شخصية.

**معيار القبول النهائي:** من الهاتف فقط: مشروع جديد → خطة قصة → لقطات → أصول مرخصة → تعليق وترجمة → رندر → QA → تنزيل MP4 ونسخة المشروع، مع حفظ واستعادة ناجحين.

## 6. تعريف الإنجاز لكل مرحلة

لا تقفل أي مرحلة إلا عند توافر:
- كود مدمج في فرع المرحلة وفرق واضح قابل للمراجعة.
- اختبارات آلية للحالات الطبيعية والحدود والأخطاء.
- اختبار تكاملي للناتج الفعلي حيث يلزم.
- تحديث README وPROJECT_STATE وملف سجل التغييرات.
- دليل CI على رأس الفرع نفسه، لا على commit قديم.
- توثيق صريح لما لم يُختبر بعد.
- عدم وجود ملفات شخصية أو أسرار أو اعتماديات غير مبررة.
